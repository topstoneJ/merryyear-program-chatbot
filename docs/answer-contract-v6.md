# 답변 검증 v6

## 변경 사항

모델 출력은 `text, source, page, categoryId, eligibilityEvidence, outcome` 여섯 필드다. 본문·근거를 작성한 뒤 `outcome` 하나에서 서버가 판정·확인 상태·질문 대상·검토 표시를 결정한다. AI가 여러 중복 판정값을 따로 써서 서로 충돌하던 경로를 제거했다. 개인 전체 자격 판정은 단순한 `eligible/ineligible` 대신 `all_personal_criteria_confirmed_met/personal_disqualifier_confirmed_without_exception`으로 범위를 명시한다. 개인 자격 판정이 아닌 응답의 불필요한 자격 메타데이터는 판단 근거로 사용하지 않는다. 개인 자격 판정의 원문·사용자 근거 검증은 유지한다.

개인 자격의 `eligibilityEvidence`도 모델이 원문을 다시 쓰지 않는다. `policyEvidenceId, userMessageId, result`로 연결하면 서버가 실제 원문 행과 실제 사용자 메시지를 조립한다. 없는 ID·이전 AI 답변·모델이 지어낸 인용은 허용하지 않는다. ID 존재는 의미 정확성의 증명이 아니므로 자격 판단에는 별도 의미 검수가 여전히 필요하다.

사업 답변은 `질문·활성 원문 → 초안 → 계약 검사 → 별도 근거 검수 → 서버 검증 → 표시·기록` 순서로 처리한다. 운영 중인 OpenAI, Gemini, Anthropic 어댑터에 같은 규칙을 적용한다. 임의의 다른 API 엔드포인트까지 지원한다는 뜻은 아니다.

- 검수 호출은 질문 충족, 근거, 수치, 필수 조건, 판정, 문의 필요성의 여섯 항목을 확인한다. 같은 설정 모델의 별도 호출이므로 독립적인 정답 보증이나 사람 검수를 대신하지 않는다.
- 서버가 활성 원문의 행과 최종 표시 답변의 각 문장에 ID를 붙인다. 검수 모델은 각 문장 ID와 근거 행 ID를 연결하고 뒷받침·모순·미명시·비정책 문장을 구분한 후 최종 검수 항목을 판단한다. 서버는 모든 문장을 정확히 한 번 검사했는지, ID 존재와 핵심 출처 포함 여부, 근거 섹션·사용자 입력의 금액, 명시된 계산식을 확인한다. 모순 문장을 포함한 응답은 최종 검사값이 모두 통과여도 차단한다. 숫자가 원문에 있다는 사실만으로 그 숫자의 적용이 맞다는 뜻은 아니며 의미 검수도 필수다.
- 특정 품목 지원 여부를 단어 중복·동일 섹션 내 무관한 금지 문구로 판정하던 검사를 제거한다.
- 순수 연락처 질문만 고정 안내로 답한다. 담당자가 언급된 정책·절차 질문은 정상 생성·검수 경로를 거친다.
- 실패 시 오류 코드와 이전 실패 초안, 문제가 있는 문장과 서버에서 확인한 원문을 데이터로 전달해 한 번 수정·재검수한다. 계산은 원문·사용자 입력의 숫자와 대조하고 서버에서 직접 검산한 산술 관계만 보충한다. 검수 모델의 자유 형식 지시나 근거 없는 계산은 전달하지 않는다. 실패 초안은 지시나 사실 근거가 아니다. 계속 실패하면 `answer_verification_failed` 오류이며 사업 기준 미명시·지원 불가·담당자 문의 답변으로 바꾸거나 상담 답변으로 저장하지 않는다.
- 출력 출처·쪽수는 검수에서 실제 선택한 근거 섹션에 연결한다. 동일 정책이 여러 활성 문서에 있는 경우 검수한 문서를 표시하며, 원문 확인을 생략하지 않는다.
- 공급자 429는 `ai_rate_limit`로 반환하고 즉시 반복 호출하지 않는다. 검수 실패·한도 초과·생성 오류도 최종 정확도 평가의 실패 분모에 포함한다.
- 답변 검증이 끝나면 화면에는 초당 30자 속도의 타이핑 애니메이션으로 표시한다. 접근성 도구와 품질검사기는 `[data-answer-text="true"][data-answer-complete="true"]`에 있는 완성 답변을 즉시 읽을 수 있다. 동작 줄이기 설정이 켜진 환경에서는 애니메이션 없이 전체 답변을 표시한다.

## 호출·비용·운영

일반 정상 답변은 생성 1회+검수 1회다. 수정이 필요하면 최대 4회이며 기존보다 호출 비용이 증가한다. 공급자의 요청·토큰 한도는 별도 용량 관리가 필요하다. 순수 연락처 조회 등 서버가 직접 답하는 제한된 경로는 AI 검수를 호출하지 않는다.

검증을 생략해 6초를 맞추지 않는다. 지연 목표는 실제 운영에서 측정하며 네트워크·사용량 기록·재시도에 따라 초과할 수 있다. 공급자나 모델 설정은 이 변경으로 바꾸지 않는다.

## 검증 수준

`pnpm test`는 빌드와 자동시험이다. 시험의 기본 모의 검수 응답은 전송 경로 확인용이지 의미 정확도 측정용이 아니다. 새 회귀시험은 근거 조작, 금액 조작, 문의 회피 판정, 재시도, 제공자 변환, 요청 한도, 저장 차단을 검사한다.

실제 API 표본 검사는 동작 확인이지 99% 인증이 아니다. 11회차 620문항을 동일 자료·모델·코드로 고정해서 모두 다시 답하고 원문 기준으로 독립 평가해야 한다. 614개 이상 정상이어야 그 세트에서 99% 이상이며 일반화된 정확도 보증은 아니다. 정상 답변에는 피드백을 쓰지 않고, 이상 답변에는 100자 이내 개조식으로 남긴다. 정답·오답 외에 생성오류도 별도 집계하되 정상으로 계산하지 않는다.

운영 자료·시험 질문·키는 저장소에 넣지 않는다. 기존 답변 계약의 판정 조합과 제공자 설정은 [v5 문서](answer-contract-v5.md)를 참고하되 호출 횟수와 실패 처리는 본 문서가 대체한다.
