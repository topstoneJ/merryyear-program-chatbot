# 사업 안내 v4 답변 규칙 적용

기준 소스는 배포 버전 6의 `f55d029bceba07771bdfd2c92c7e28ab24ea4224`입니다.

## 적용 내용

- `app/answer-rules.ts`가 실제 시스템 지시와 관리자 규칙 설명의 공통 정의입니다. 질문 해석 → 적용 자료 선택 → 근거 확인 → 판정 → 표현 설정 → 출력 검사 순서로 처리합니다.
- 기관별 답변 옵션과 질문 유형, 실행 모델은 기존 저장 설정에서 읽습니다. 공통 규칙과 표현 설정을 중복해서 모델에 전달하지 않습니다.
- 개인 전체 신청 자격과 비용·품목·절차의 제한을 구분합니다. 사용자 조건 부족과 정책 자료 부재도 구분합니다.
- 자료는 사업 ID·활성 상태를 서버에서 제한합니다. 구조화 섹션의 제목·본문·페이지를 보존하고 `review_required` 섹션과 그 섹션을 인용한 충돌 캐시는 제외합니다.
- 실제 자료 ID와 해당 PDF의 알려진 페이지를 검증합니다. 페이지가 확인되지 않은 자료는 0으로 기록합니다. 출처 없는 사실 답변은 자료 부족 안내로 바꿉니다.
- 고정 사업 예시와 모호한 숫자 추출 계산 경로를 제거했습니다. 사용할 자료가 없으면 모델을 호출하지 않고 자료 부족을 안내합니다.
- 말투를 고치기 위한 전체 답변 재생성을 제거했습니다. 결정값은 상담 저장과 조회 시 그대로 보존하며, 시스템 오류는 자료 충돌과 구분합니다.
- 기존 공개 범위·데이터·모델 설정을 유지합니다. 스키마 변경은 없습니다.

## 검증

2026-09-10 기준 `pnpm test`에서 Next.js 배포 빌드와 회귀 테스트 143건이 통과했습니다. 모의 응답을 사용해 API 요청 구성, 개인정보 마스킹, 자료 제외, 출처·페이지 검증, 판정 보존과 예외 처리를 확인했습니다. 기존 화면 테스트의 오래된 기대값과 모듈 로딩도 현재 구현에 맞췄습니다.

실제 모델의 기존/개선 프롬프트 A/B 평가는 실행하지 않았습니다. 출처 검증은 문서 식별과 페이지 존재를 확인하며, 답변의 모든 문장이 원문에서 논리적으로 도출되는지 증명하지는 않습니다. 기존 confidence 값은 표시용 단계값이며 측정된 정확도나 확률이 아닙니다.

배포 워크플로에서도 같은 `pnpm test`를 실행하며, 성공한 standalone 빌드만 Azure App Service에 배포합니다.

## 후속 검증

실제 운영 모델과 비운영 자료를 사용할 수 있는 평가 환경에서 자격·항목 제한·자료 충돌·날짜·조건 변경·자료 속 악성 지시를 비교해야 합니다. 잘못된 자료 자체의 교정, 효력일 메타데이터, 여러 결론과 여러 출처를 구조화하는 계약은 별도 개선 과제입니다.
