2.1 문제 정의
지원사업 상담에는 신청 대상, 제출서류, 일정처럼 같은 내용을 반복해서 묻는 문의가 많습니다. 동시에 개인 상황이나 예외조건에 따라 판단이 필요한 질문도 들어옵니다. 단순 문의와 복잡한 상담이 한 채널에 섞이면서, 담당자는 본연의 업무에 집중하기 어렵습니다.

이 계산에는 다음과 같은 정성적인 문제는 포함되지 않았습니다.
* 이용자가 담당자 부재 또는 야간, 주말에 답을 기다려야 하는 것
* 담당자가 잦은 문의에 응대하면서 업무 연속성이 저하되는 것
* 여러 담당자를 거치거나 순간 착오로 답변에 편차가 생기는 것 등
시중에는 채널톡 같은 솔루션이 있지만, 대부분 커머스 환경에 맞춰져 있습니다. 자료를 한 번 설정하고 오래 사용합니다. 비영리기관은 다릅니다. 여러 사업이 동시다발적으로 운영되며 모집마다 대상, 조건, 지원 내용과 제출 서류가 다릅니다. 하지만 규모가 작아 시중 솔루션을 사용하기에는 편익 대비 비용이 많이 듭니다.
그래서 우리는 비영리단체에 최적화된 솔루션이 필요했고, 다음 조건을 갖춘 챗봇을 만들었습니다.
* 담당자가 자리를 비운 시간에도 기본 문의에 답할 것
* 기관이 승인한 자료만 근거로 쓸 것
* 특수사례는 필요한 조건을 추가로 확인하여 기준에 적용할 것
* 답변에 필요한 자료가 부족하면 추측하지 않을 것
* 최종 판단이 필요한 문의는 담당자에게 넘길 것
* 사업자료를 쉽게 추가·수정·비활성화할 수 있을 것
* 자료를 바꾸면 관련 질문과 자료 충돌을 다시 점검할 것
* 담당자가 상담 기록을 검토하고 기준을 계속 보완할 수 있을 것
* 비용이 저렴할 것
이 챗봇을 통해 전화상담을 줄이는 데 그치지 않고, 지원사업 데이터를 쉽게 관리하면서 일관된 안내를 제공하는 운영체계를 구축하고자 합니다.
2.2 AI 솔루션 소개
솔루션 개요
‘열매나눔재단 사업 안내 챗봇’은 기관이 등록한 사업자료를 찾아 이용자의 자연어 질문에 답하는 웹 서비스입니다. 별도 프로그램을 설치할 필요 없이 사업을 선택하고 질문하면 됩니다.
AI는 질문의 뜻과 앞선 대화를 파악한 뒤 선택한 사업의 공개·활성 자료에서 근거를 찾습니다. 자료만으로 답을 확정하기 어려우면 필요한 정보를 되묻습니다.
관리자는 사업자료와 응답 기준을 직접 관리합니다. 상담 기록에서 부족한 답변을 찾아 자료를 보완하거나 FAQ로 추가하여, 실제 상담을 토대로 운영 기준을 충돌없이 누적합니다.

주요 기능
1. 사업별 자연어 질의응답
일상적인 표현으로 물어도 질문 의도를 파악합니다. 후속 대화에도 기존 맥락을 참고해 답변합니다.
2. 등록자료에 근거한 답변
관리자가 사업별로 등록한 자료만 답변에 사용합니다.
3. 근거 부족과 자료 충돌 처리
자료에 없는 답변을 만들지 않습니다. 자료가 충돌하면 관리자에게 알리고, 답변에 필요한 자료가 없거나 최종 판단이 필요한 질문은 담당자 확인으로 연결합니다.
4. 개인정보 보호
이름·주민등록번호·상세주소·계좌번호 같은 불필요한 개인정보를 요구하지 않습니다. 주민·외국인등록번호, 운전면허·여권번호와 전화·이메일 패턴을 외부 AI 전송과 신규 상담 저장 전에 가립니다. 이름·주소 등 모든 개인정보를 자동 탐지하지는 않습니다. 확인이 필요할 때도 연령대, 가구원 수, 소득 범위처럼 개인을 식별할 수 없는 정보만 묻습니다.
5. 사업자료 등록과 구조화
관리자는 PDF·웹페이지·텍스트 자료를 등록할 수 있습니다. PDF는 검색 가능한 마크다운 형태로 바꾸되 근거 페이지는 보존합니다. 자료의 공개 여부와 답변 활용 여부도 나눠서 관리합니다.
6. 상담 검토와 답변 보완
상담내역에서 질문 유형, 답변 판정, 검토 필요 여부를 확인합니다. 부족한 답변은 실무자가 수정하고 사업자료로 보완합니다.
7. 기관별 운영 설정
기관명, 로고, 색상, 안내 문구를 바꿀 수 있습니다. 답변 길이·말투·형식과 판정 기준도 관리합니다. 관리자 계정마다 상담·자료·설정 화면의 접근 권한을 부여합니다.
8. 운영과 비용 관리
GitHub Actions에서 검증된 코드만 Azure App Service에 자동 배포합니다. 운영 데이터와 소스코드를 분리해 새 버전을 배포해도 기존 자료가 유지되도록 구성했습니다. API 사용에 따른 모델별 호출 횟수와 예상 비용을 확인할 수 있습니다.

AI가 맡는 일과 사람이 맡는 일
AI는 이용자의 질문과 대화 맥락을 해석합니다. 선택한 사업자료에서 대상·지원항목에 맞는 근거를 찾고, 근거가 충분한지 확인합니다. 그 결과에 따라 답변, 추가 질문, 자료 부족, 담당자 확인 중 하나를 선택합니다.
PDF와 웹자료를 사업 안내에 맞게 정리하고 상담내역을 유형별로 분류하는 일에도 AI를 씁니다. 다만 운영 기준을 정하고 예외를 판단하는 일, 신청·선정·지급처럼 이용자에게 영향을 주는 판단은 사람이 맡습니다.
AI를 활용한 이유
지원사업 문의는 같은 뜻이라도 표현이 제각각이고, 개인의 상황에 따라 확인할 조건도 달라집니다. 고정 메뉴나 FAQ만으로는 질문마다 다른 맥락을 따라가기 어렵습니다.
AI는 여러 자료에서 관련 근거를 찾아 이용자의 표현에 맞춰 설명할 수 있습니다. 부족한 정보를 스스로 물어볼 수 있습니다. 기본 문의는 시간에 구애받지 않고 안내하고, 실무자는 특수사례와 사례관리처럼 사람의 판단이 필요한 업무에 집중할 수 있습니다.
AI가 없었다면 어려웠던 부분
AI가 없다면 질문 표현마다 FAQ를 따로 작성해야 합니다. 실무자는 공고문·운영지침·상담 사례를 매번 찾아 대조해야 합니다. 특히 아래 작업은 고정 규칙만으로 계속 관리하기 어렵습니다.
* 표현이 다른 질문에서 같은 의도 찾기
* 여러 조건이 섞인 질문에서 필요한 근거 고르기
* 정보가 부족할 때 필요한 내용을 되묻기
* 자료 충돌과 적용 범위 가려내기
* 같은 기준을 이용자가 이해하기 쉬운 말로 설명하기
AI 성능을 높이기 위해 시도한 세 가지
1. 멀티모달 자료를 결합하고 피드백하는 프로세스
사업정보가 웹사이트, 텍스트와 PDF에 나뉘어 있어 한 가지 자료만으로는 정확한 답변을 만들기 어려웠습니다. 세 종류의 자료를 함께 검색하도록 구성하고, PDF는 제목·표·페이지 정보를 유지한 마크다운으로 변환했습니다. 변환 과정에서 내용이 빠지거나 잘못 인식되지 않았는지 사람이 원문과 비교할 수 있습니다.
상담내역 중 미흡한 답변이 발견되면 관리자가 유사 질문에 대응하는 보완답변을 추가하거나 자료 자체를 수정할 수 있습니다. 이를 통해 자료 등록, AI 답변, 사람의 검토, 자료 보완이 반복되는 품질개선 구조를 만들었습니다.
2. API와 소스코드 효율 개선을 통한 응답속도 향상
Gemini API는 답변 생성에 시간이 오래 걸리는 경우가 있어, 답변 품질과 처리 속도를 비교한 뒤 GPT API로 변경했습니다. 소스코드에서는 질문을 처리할 때마다 반복되던 데이터 조회를 제거하고, 함께 처리할 수 있는 작업은 동시에 실행하도록 개선했습니다. AI가 만든 결과도 한 번만 읽어 답변 확인과 사용량 기록에 함께 사용했습니다. 이를 통해 답변의 정확성을 유지하면서 불필요한 AI 호출과 서버 처리 시간을 줄였습니다.
3. 예상 질문을 이용해 반복적으로 품질검사
기본 질문뿐 아니라 표현을 바꾼 질문, 개인 사례, 여러 조건이 섞인 질문과 예외 요청 등을 포함해 최대 620개의 예상 질문을 만들었습니다. 사람이 답변을 확인해 잘못된 단정, 조건 누락, 출처 오류와 문의처 누락을 기록하고, 사업자료·빠른 답변·답변 기준을 수정한 뒤 같은 유형을 다시 검사했습니다.
동일한 기본형 검사에서 내용 정확도는 1회 64.2%에서 2회 89.8%, 4회 90.0%, 5회 99.8%로 높아졌습니다. 이후에는 내용뿐 아니라 답변 옵션과 말투·형식이 설정대로 적용되는지도 별도로 검사했습니다.
개발 과정
1단계: 초기 챗봇 구현  (2026.07.22–07.23)
Codex Sites를 활용해 사업 공고와 지식자료를 근거로 답하는 챗봇을 구현했습니다. 소득 계산, 사업·지식자료·상담 기록 관리, 예상 질문 기능도 추가했습니다. 이 단계에서 챗봇이 일반 지식으로 추측하지 않고, 등록된 자료를 우선 사용하도록 기본 원칙을 정했습니다. 하지만 지정된 키워드에만 반응하여, 답변 품질이 매우 낮았습니다.
2단계: 답변 품질과 사용성 개선  (2026.07.24–07.31)
Gemini API를 사용해 답변 품질을 큰 폭으로 개선했습니다. 중복되는 답변 근거를 제거하고 링크와 문단 형식을 정리했습니다. 긴 답변은 짧은 문장과 항목으로 나눴습니다. 로딩 화면, 답변 불릿 등을 정비해 실제 이용자가 사용하기 쉬운 형태로 개선했습니다.
3단계: 관리자 기능과 보안 강화 (2026.08.24–08.31)
PDF 자료를 마크다운 형식으로 저장하고 구조화해 편집할 수 있도록 개선했습니다. AI의 자료 인식이 용이해져 답변속도가 빨라졌습니다. 기관 브랜딩도 화면에 반영했습니다. 관리자 로그인, 계정별 권한, 사업별 관리 기능을 추가했습니다. API 키는 암호화해 보관하도록 변경했습니다. 담당자가 개발자 도움 없이 자료와 설정을 관리할 수 있게 하는 데 중점을 뒀습니다. 상담 분류, 필터, 검토 상태와 통계 기능도 추가했습니다.
4단계: 대화 문맥과 개인정보 처리 개선 (2026.09.01-2026.09.08)
같은 대화에서 이전 질문의 맥락이 유지되도록 세션 기능을 보완했습니다. API 사용량 관리와 PDF 처리 안정성도 함께 개선했습니다. 개인정보보호를 위해 주민등록번호 등 민감정보 입력을 제한하는 규칙을 삽입했고 개인정보처리방침을 메인화면에 추가했습니다.
5단계: 배포 (2026.09.09–09.16)
운영 서버는 Microsoft Azure 한국 중부 리전을 선택했습니다. 국내 이용자를 대상으로 하는 점과 데이터 처리 위치, 응답 속도를 고려했습니다. 개발 저장소에는 설치·운영 방법과 개발 과정을 정리했고, 최종 제출 저장소에는 소스코드와 문서를 반영할 예정입니다. 답변 출력, 설정값, 자료 충돌 시 상담 안내 등 핵심 기능은 자동 테스트로 확인했습니다. API를 Gemini에서 OpenAI GPT로 교체하고, 답변 속도를 평균 20초에서 4초대로 낮췄습니다.
2.3 이용자용 가이드
1. 이용자용 챗봇에 접속합니다.
2. 안내받을 사업을 선택합니다.
3. 궁금한 내용을 자연어로 입력합니다.
4. 챗봇이 추가로 묻는 내용이 있으면 답합니다.
5. 답변에 표시된 조건과 출처를 확인합니다.
6. 신청·선정·지급 등 최종 판단이 필요한 사항은 공식 공고문이나 담당자에게 다시 확인합니다.
이름, 주민등록번호, 상세주소, 계좌번호 같은 개인정보는 입력하지 않습니다. 챗봇 답변은 등록자료를 바탕으로 한 참고 안내이며 신청 완료, 선정 확정, 지급 확정을 대신하지 않습니다. 자료가 부족하거나 충돌하면 확정적인 답을 하지 않을 수 있습니다.
2.4 관리자용 가이드
관리자는 기관명, 로고, 색상, 기본 문구를 먼저 설정합니다. 이후 사업을 만들고 PDF·웹페이지·텍스트 자료를 등록한 뒤 공개 여부와 답변 활용 상태를 지정합니다. 구조화된 내용과 근거 페이지를 확인하면 답변 길이·말투·형식 등 응답 설정을 조정할 수 있습니다.
운영을 시작한 뒤에는 예상 질문과 실제 질문으로 답변을 점검합니다. 상담내역에서 검토가 필요한 답변을 찾고, 부족한 내용은 사업자료나 빠른 답변으로 보완합니다. 자료를 추가·수정·삭제했을 때는 충돌 검사와 관련 질문 회귀검사를 다시 실행합니다. 모델별 사용량과 예상 요금도 관리자 화면에서 확인합니다.
가이드 페이지에서 관련된 안내사항을 확인할 수 있습니다. 또한 가이드 챗봇을 통해 대화형으로 내용을 파악할 수 있고 계정 권한이 허용하는 선까지 상담 내용에 대한 분석이 가능합니다.

4.5 개인정보·AI 윤리
어떤 정보를 수집하고 어디에 사용하는가?
챗봇은 운영과 품질 개선을 위해 이용자가 선택한 사업, 질문과 답변, 이용 시각, 답변 판정, 검토 상태 등 저장할 수 있습니다. 이름, 주민등록번호, 상세주소, 계좌번호는 사업 안내에 필요하지 않으므로 입력하지 않도록 안내합니다. 관련 정보는 답변을 만들기 위해 설정한 외부 AI 공급사로 전송될 수 있습니다. 공급사별 보관·학습·삭제 조건은 계약 시점의 약관과 계정 설정을 확인해야 합니다. API의 응답 저장 옵션만으로 실제 보관 조건을 보장하지 않습니다.
개인정보 수집·활용 동의가 필요한가?
운영 과정에서 이용자의 질문을 저장하거나 외부 AI로 전송하는 경우에는 수집 항목, 이용 목적, 보관기간, 삭제 방법과 동의 거부에 따른 영향을 개인정보처리방침으로 고지합니다. 선택한 외부 AI 공급사 이용에 따른 개인정보 처리위탁과 국외 이전도 실제 데이터 흐름에 따라 명시합니다. 국외 이전을 원하지 않는 이용자는 챗봇 대신 사업 담당자에게 문의할 수 있도록 안내합니다.
이용자에게 어떻게 알리는가?
이용 화면에는 개인정보와 민감정보를 입력하지 않도록 안내하고, 챗봇이 등록된 사업자료를 바탕으로 정보를 제공한다는 점을 표시합니다. 자료에 없는 예외사항은 담당자에게 문의하도록 안내하며, 신청 자격의 인정과 선정·지원 여부는 사업별 심사 절차에 따라 결정된다는 점을 알립니다.
개인정보처리방침에는 상담기록의 수집 항목과 목적, 보관기간, 삭제 방법, 외부 AI 전송 범위를 명시합니다. 또한 실제 리전을 확인한 Azure 저장 정보와 선택한 외부 AI 공급사를 통해 해외에서 처리될 수 있는 정보를 구분하여 설명합니다.
AI 오류를 사람이 어떻게 확인하고 고치는가?
챗봇은 기본적으로 근거가 부족하거나 예외 판단이 필요한 질문은 임의로 답하지 않고 담당자 전화 문의로 안내합니다. 잘못된 답변이 출력되는 경우 사업자료를 보완한 뒤, 관련 질문을 다시 검사하여 같은 오류가 반복되지 않도록 해야 합니다. 만약 해당 사례로 피해가 발생한 경우 재접수나 서류 보완 등 가능한 조치를  검토해야합니다.
