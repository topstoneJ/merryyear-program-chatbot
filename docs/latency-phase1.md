# 정확도 유지형 응답시간 개선: 1차

2026-09-14. 기준 배포: `0179d0b12c7a0fc8a9f877b2e68cdfa572c604f2`.

## 적용 범위

- DB 객체별 기본 상담 분류 초기화를 한 번만 수행한다. 동시 호출은 같은 초기화 작업을 기다리고 실패하면 다음 요청에서 재시도한다. 분류 목록 자체는 캐시하지 않으므로 이름 변경·교체·삭제가 계속 반영된다.
- 예열 후 일반 답변마다 수행하던 기본 분류 조건부 INSERT 16개와 해당 초기화 트랜잭션 2개를 제거한다. 첫 요청에서는 초기화를 수행한다.
- 답변 설정과 암호화된 API 키를 같은 행 조회로 읽어 중복 SELECT 1회를 제거한다. 요청 단위로만 재사용하고 키 변경·명시적 사용 중지를 장기 캐시하지 않는다.
- 설정과 분류 조회를 병렬 실행한다. 자료를 읽고 공개 범위를 확인하는 순서는 유지한다.
- 채팅 전용 API 경로에서 모델 응답 JSON을 한 번 읽는다. 성공·HTTP 오류·파싱 오류·네트워크 실패 각각의 사용량 기록은 계속 기다린다. 상담도 현재 동기 저장을 유지한다.
- `Chat timing` 로그에 구간별 시간과 응답 상태를 기록한다. 질문·답변·키·오류 상세는 기록하지 않는다. 응답의 `Server-Timing`은 총 서버 처리 시간만 표시하며 `Cache-Control: no-store`를 설정한다.

## 유지한 정확도 관련 동작

모델·생성 설정·전체 자료·전체 대화·시스템 지시·출처 및 페이지 검증·연락처 검증·마스킹·최종 응답 형식은 유지했다. 원문 캐시, 검색에 의한 자료 축소, 대화 요약, 모델 출력 스트리밍, 저장 비동기화는 이번 배포에 포함하지 않는다.

## 검증

- `tests/fixtures/chat-before-latency.fixture`는 기준 배포의 채팅 처리 코드다. 변경 후 코드와 함께 동일한 조건에서 실행하여 일반 질문, 자격/제외 판정, 충돌, 근거 부재, 잘못된 출처/JSON, 키 없음, 비공개 사업, 표현 설정, 사용자 정정, 긴 대화, 큰 자료, 관리자 질문 등 14개 시나리오의 모델 요청 전체·최종 답변·상담 저장값을 비교한다.
- 초기화 동시성/실패 재시도, 실시간 분류명 변경, API 키 사용 중지, API 응답 단일 파싱 및 실패별 사용량 기록, 성능 로그의 민감정보 미포함을 추가 검증한다.
- 전체 빌드와 테스트 및 배포 데이터 제외 검사를 통과한 코드만 기존 GitHub Actions로 배포한다.
- 모의 응답 동등성은 모델 입력과 검증 경로의 유지 근거다. 실제 모델 정확도를 통계적으로 입증한 300개 시나리오 평가는 아직 수행하지 않았다. 이후 입력을 바꾸는 최적화는 별도 평가가 필요하다.

## 측정·복귀

`generation`은 설정 조회, 모델 호출 및 사용량 기록과 검증을 포함하는 상위 구간이다. `configuration`, `model`, `usage`, `validation`과 중복 합산하지 않는다. `model`은 첫 토큰이 아니라 본문 전체 수신/파싱까지의 시간이다. 서버 시간은 브라우저 왕복·렌더 시간을 포함하지 않는다.

대표 질문의 전후 점검은 운영 이상 유무 확인이며, 적은 표본만으로 평균 개선율이나 p95 달성을 주장하지 않는다. 충분한 운영 표본에서 전체 응답시간과 구간별 비중을 비교한다.

DB 스키마와 운영 데이터 변환이 없어 변경 커밋을 되돌리는 프로그램 배포로 복귀할 수 있다. 분류의 기존 tombstone 및 모든 상담/사용량 기록을 그대로 유지한다.
